The problem

Personalizing an event means collecting a hundred small answers.

A conference tote with each attendee's name. A retreat crewneck showing a star map of the venue on the day you meet. The item is easy to choose. Collecting what the vendor needs to make one per person is the work.

For every attendee the organizer asks for a size, a spelling, a preference, keeps the answers in a spreadsheet, and chases the people who have not replied. Then each row gets re-typed into the vendor's checkout. A wrong size or a dropped letter shows up after the box arrives.

A walkthrough

One event, from the guest list to the order.

This is the recorded run in the demo. The event is the 8th Annual Eastern Canada Astronomy Symposium in Toronto. Every attendee should leave with a crewneck showing a star map of the venue on the event date, printed with their name. Three attendees have replied so far.

1

Create the event.

The organizer fills in the title, the venue, and the date, adds the RSVP questions, and publishes. Publishing creates the link attendees reply through. This is the RSVP flow that already exists.

Tokuchu — New event
2

Describe the item in one sentence.

In the guest experience the organizer types the request: personalized star map crewnecks for everyone attending. The search runs over WebMCP, ranks Customworks and its star map crewneck, and the organizer picks it. The store's get_customization tool returns the fields the shirt needs: the star map location and date, which the event fills, and the printed name, which each attendee fills.

Tokuchu — Guest Experience
3

The product's requirements become the RSVP questions.

Whatever the shirt needs that only an attendee can give, their name for printing and their size, goes to each attendee as a request. The app records who has answered and resends to whoever has not.

Tokuchu — Attendees
4

Review the records and approve.

Every response is a row in a grid, one column per field, the way a spreadsheet would hold it. When the answers look right, the organizer approves the specs for the vendor. Approval locks each attendee's answers.

Tokuchu — Attendees
5

The store receives one configured shirt per attendee.

On approval the app calls the store's add_customized_to_cart tool. The store's cart fills with a personalized crewneck for each attendee, the star map and the name set on every line, and the organizer opens the checkout link to review and pay. The organizer never re-typed a detail into the store.

Why WebMCP

The store hands the agent its own requirements.

Before WebMCP, reading a store's personalization options meant scraping its checkout page or building an integration for that one vendor. Each new store was new code. WebMCP lets a store publish its search, its product options, and its cart as tools an agent calls directly. Tokuchu reads the exact fields a vendor needs and writes back a configured order, and the same code works for any store that speaks WebMCP.

search_catalog

Find the store

The search calls Shopify's catalog tools over WebMCP and ranks the store's product with no per-store setup.

get_customization

Read the requirements

The store's own tool returns the fields the product needs and their limits. Each field the app cannot fill from the RSVP or the event becomes a question for the attendees.

add_customized_to_cart

Write the order

The store's second tool adds one configured line per attendee through Shopify's cart and returns a checkout link the organizer opens.

Orders and fulfillment use Shopify's GraphQL Admin API over a client credentials grant. Tokuchu never stores a card.
